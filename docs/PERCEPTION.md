# Bounded visual perception service

`chreatures/perception.py` is an optional asynchronous sensory organ. It sends
one creature's field-of-view image, or at most four short-sequence frames, to a
pinned vision-language model and returns uncertain object and affordance
hypotheses. It does not receive world state, positions, resident/account IDs,
goals, or actions. A controller may use a response as sensory evidence; the
response is never an authoritative action script.

The HTTP process in `scripts/serve_perception.py` binds only to loopback. The
default backend is `off`, which returns `status: unavailable` rather than
inventing observations. Model import or startup failures also remain visible
through `/v1/health` and every response.

## Model and native API

The deployed backend is
[`HuggingFaceTB/SmolVLM2-500M-Video-Instruct`](https://huggingface.co/HuggingFaceTB/SmolVLM2-500M-Video-Instruct)
at commit
[`7b375e1b73b11138ff12fe22c8f2822d8fe03467`](https://huggingface.co/HuggingFaceTB/SmolVLM2-500M-Video-Instruct/tree/7b375e1b73b11138ff12fe22c8f2822d8fe03467).
Its model card declares Apache-2.0 and image, multi-image, and video input.
The implementation follows the native Transformers
[`AutoProcessor` / `AutoModelForImageTextToText` flow](https://huggingface.co/docs/transformers/en/model_doc/smolvlm),
including `apply_chat_template`, `generate`, and `get_image_features`.

The snapshot is on hbox at
`/tank/chreatures/models/SmolVLM2-500M-Video-Instruct`. The service requires a
local revision marker that exactly matches the commit above and uses
`local_files_only=True`; it cannot silently fetch or move to another model at
startup.

## Request boundary

Send JSON to `POST /v1/perceive`:

```json
{
  "request_id": "mica-eye-1842",
  "source": {
    "sensor_id": "mica.left-eye",
    "world_sequence": 1842,
    "model_time": 92.10,
    "captured_at": 1788625012.25,
    "provenance": "resident_fov"
  },
  "frames": [
    {"mime_type": "image/jpeg", "data_base64": "..."}
  ],
  "include_dense_feature": false
}
```

`provenance` is required and is either `resident_fov` or `external_test`.
The latter prevents a benchmark or setup image from being described as
something a resident experienced. Each decoded JPEG/PNG is limited to 1.5 MB
and 1.5 million pixels; all frames together are limited to 4 MB. The entire
HTTP body is limited to 5.5 MB. Unknown request and source keys are rejected,
which keeps whole-world data and identity fields outside this interface.

An accepted inference has this shape:

```json
{
  "request_id": "mica-eye-1842",
  "source": {"sensor_id": "mica.left-eye", "world_sequence": 1842},
  "status": "ok",
  "scene_summary": "...",
  "objects": [
    {"id": "o1", "label": "...", "confidence": 0.7, "uncertainty": 0.3}
  ],
  "affordances": [
    {"object_id": "o1", "action": "inspect", "confidence": 0.6,
     "uncertainty": 0.4}
  ],
  "uncertainty_kind": "complement of model-self-reported confidence; uncalibrated"
}
```

Affordances are bounded to a 48-character action phrase generated by the
model. They remain descriptive hypotheses and are never executed directly.
Confidence is self-reported by the generative model and is not a calibrated
probability. Malformed model text is returned as `invalid_model_output`; the
service does not convert it into a pretend detection. `scene_summary` is a
deterministic joining of the accepted model-generated object labels, rather
than a second inferred claim.

With `include_dense_feature: true`, the result also contains the mean of the
model's native modality-projected image tokens. This is a real model feature,
not a handcrafted scene vector. It is large and should be requested only by a
consumer that needs it.

## Ordering and backpressure

`world_sequence` is monotonically increasing per `sensor_id`. A request at or
behind the latest accepted sequence immediately returns `status: stale`. If a
newer frame arrives while an older inference is running, the older result is
discarded after inference and returned as stale. The default deployment uses
one model worker and two total pending requests. A full queue returns
`status: busy` without blocking the simulation.

Other explicit states are `unavailable`, `error`, and
`invalid_model_output`. Clients should treat every state except `ok` as no
semantic observation. Source sequence, simulation time, capture time,
provenance, model identity, and inference latency are echoed in each response.

## Deploy on hbox

The backend has its own environment at `/tank/chreatures/envs/perception` and
does not modify the MaleCNS process environment. The pinned runtime packages
are PyTorch 2.9.1 for ROCm 6.3, torchvision 0.24.1, Transformers 4.57.1, and
Pillow 11.3.0. Start it from a synchronized project source directory:

```sh
HSA_OVERRIDE_GFX_VERSION=10.3.0 \
PYTHONPATH=/tank/chreatures/perception-src \
PYTORCH_KERNEL_CACHE_PATH=/tank/chreatures/cache/perception-pytorch \
HF_HOME=/tank/chreatures/cache/huggingface \
/tank/chreatures/envs/perception/bin/python \
  /tank/chreatures/perception-src/scripts/serve_perception.py \
  --backend smolvlm2 \
  --model-path /tank/chreatures/models/SmolVLM2-500M-Video-Instruct \
  --device cuda --dtype float16 --max-new-tokens 128 \
  --max-workers 1 --max-pending 2 \
  --bind 127.0.0.1 --port 8775 \
  --pid-file /tank/chreatures/runs/perception/perception.pid
```

Tunnel the loopback service when the habitat runs elsewhere:

```sh
ssh -N -L 18775:127.0.0.1:8775 hbox
curl http://127.0.0.1:18775/v1/health
```

## Measured external-image check

The first live check used the bee photograph linked from Hugging Face's
[official image-to-text task documentation](https://huggingface.co/docs/transformers/en/tasks/image_text_to_text).
It is an external test image and was submitted with
`provenance: external_test`; no resident has seen it. The original and bounded
field-of-view copy remain on hbox:

| File | Size / SHA-256 |
| --- | --- |
| `/tank/chreatures/runs/perception/external-bee.jpg` | 5,373,297 bytes / `8b21ba78250f852ca5990063866b1ace6432521d0251bde7f8de783b22c99a6d` |
| `/tank/chreatures/runs/perception/external-bee-fov.jpg` | 768×512, 69,333 bytes / `b0068eb645b74aec38752ef9f8dd6b3ee1288e2f82a8d7ce737eb142afbd14e6` |

The native dense-feature path completed in 7.89 seconds and returned 960
dimensions; the values hashed to
`372e27c4f359d99b97aa4e6c55ad66b7e18a736e855c86de36439f2c3d16eaac`
after canonical JSON encoding. The initial compact-JSON semantic prompt did
not reliably produce valid JSON from this 500M model, so those attempts were
reported as `invalid_model_output` rather than accepted. A smaller, explicit
`object|affordance|confidence` grammar produced this native response in 1.885
seconds (1.900 seconds client wall time):

```json
{
  "status": "ok",
  "scene_summary": "Visible hypotheses: flower",
  "objects": [
    {"id": "o1", "label": "flower", "confidence": 1.0,
     "uncertainty": 0.0}
  ],
  "affordances": [
    {"object_id": "o1", "action": "pollinating", "confidence": 1.0,
     "uncertainty": 0.0}
  ],
  "uncertainty_kind": "complement of model-self-reported confidence; uncalibrated"
}
```

The actual response artifact is
`/tank/chreatures/runs/perception/external-bee-semantic-5.json` (1,478 bytes,
SHA-256
`db57431a18745af1c82e85649c3dbe768f20cbf53da647473183254e73a683ff`).
The model's `1.0` is visibly overconfident and illustrates why downstream code
must not treat these numbers as calibrated probabilities. The service was
stopped after validation to leave the GPU to the developmental run; it can be
started with the command above when a perception window is scheduled.

Resident field-of-view rendering is not present yet. Until the 3D renderer
submits a `resident_fov` frame, this proves only the external-image transport,
native VLM execution, dense visual feature, provenance, and failure semantics.
